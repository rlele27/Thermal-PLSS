EVA WORKFLOW - READ-ME
======================

RUNNING THE PROGRAM
Set MATLAB's Current Folder to EVA_Workflow. Run Metabolic_EVA_Sim.m first,
then PLSS_Thermal_Sizing.m. Both scripts use the visible relative filename
"+Data_Functions/EVA_Data.mat". There is no addpath, automatic path discovery,
working-directory switching, run identifier, timestamp log, or run archive.

The + prefix makes +Data_Functions a MATLAB package. Calls are explicitly
qualified in the code, for example Data_Functions.Physiology.runJOS3Profile(...). MATLAB
resolves them from the current folder without modifying its search path.
Do not remove the + prefix. Move the complete EVA_Workflow folder when sharing.

FILES AND INPUTS
Metabolic_EVA_Sim.m contains physiology inputs, both EVA scenarios, energy
accounting, the NASA comparison, reporting and physiology plots.
PLSS_Thermal_Sizing.m contains hardware/search inputs, off-nominal sizing,
sensitivity, packaging, reporting and hardware plots.
+Data_Functions contains reused numerical functions, the source-data builder,
the single MAT-file and use-case subpackages. The MIT license is in +Physiology. One-time code stays in the scripts.
The data builder is the explicit exception: it stores METMAN, nominal activity
and NASA source data. It creates a missing MAT-file and adds a missing active LCG dataset to an
existing file while preserving its current simulation/hardware results. Model constants/correlation coefficients stay in numerical
functions; adjustable operating inputs are in the main scripts.

FUNCTION SUBFOLDERS
+Data_Functions/+Data           MAT creation and simulation/sizing interface checks.
+Data_Functions/+Metabolism     Activity-to-metabolic-rate lookup.
+Data_Functions/+Physiology     JOS-3 body model and timestep integration.
+Data_Functions/+Properties     Water, oxygen and saturation-property equations.
+Data_Functions/+HeatExchangers Condenser/fin transfer and reheater sizing.
+Data_Functions/+Humidity       RH inventory, channel search and design selection.
+Data_Functions/+Reporting      Shared air/moisture summaries and table printing.

The MAT-file stays directly in +Data_Functions. Explicit calls include the
use-case package, e.g. Data_Functions.HeatExchangers.sizeAirWarmer(...).
All + prefixes are MATLAB package syntax and must be retained. No addpath is
needed when MATLAB's Current Folder is EVA_Workflow.

CURRENT DATA ONLY
EVA_Data.mat contains one Data structure:
  Data.Source.MetMan         Active METMAN lookup vectors/cells.
  Data.Source.Nominal        Nominal activity/time/rate vectors.
  Data.Source.LCGReference   NASA benchmark Raw and DynamicRawTable10 observations.
  Data.Simulation           Current physiological results, inputs and reports.
  Data.Hardware             Current hardware results, inputs and reports.

Archived workbooks, old validation records, metadata structures, schema fields,
run IDs, creation/update times and tracking fields have been removed. Current
physical histories and MATLAB tables are retained. Each script explicitly saves
the current Data structure to the same file with save(...,'-v7'); it does not
create dated files, backups or history lists. Stage 1 replaces Data.Simulation
and clears Data.Hardware. Stage 2 replaces Data.Hardware. Run stage 2 again after
changing physiology. No run-tracking system enforces that sequence.

DATA TRANSFER AND VALIDATION
Simulation.Nominal and Simulation.OffNominal each contain Metabolic, Physiology
and SizingProfile tables. buildSizingProfile assembles interval times (min),
temperatures (degC), pressure (kPa), dry-gas flow (kg/s), humidity ratios (kg/kg)
and moisture loads (g/min). validateEVAInterface checks actual required fields,
scenario labels, interval continuity and consistency with physical histories;
it does not inspect versions, run IDs or dates. Hardware uses off-nominal data
only and does not rerun physiology. Detailed scientific reports are current
results, not run archives. Plotting follows calculations and saving.

SENSITIVITY
Hardware-only changes are -50%, -10%, +10%, +50% for moisture, supply temperature
and supply RH. Temperature changes multiply the configured Celsius value; RH
changes are relative percentages. Trials retain prescribed physiological histories.
Reports include average/peak cooling, condenser/reheater volume, feasibility and
combined-volume change. Condenser volume includes bases/routing. Reheater volume
excludes external fittings. Incompatible target/dew-point bounds are infeasible.

LITERATURE AND LIMITATIONS
JOS-3: Takahashi et al. (2021), Energy and Buildings 231, 110575.
https://doi.org/10.1016/j.enbuild.2020.110575
Reference port revision: 3c74ee2; original MIT license is retained.

METMAN: BVAD Rev.2 (2022), Table 3-26, 95th-percentile reference. The nominal
schedule is the original activity CSV. Off-nominal replaces the final 250 min
with walking using the resistance reference rate and configured Mars/suit scaling.

LCG: Bue et al. (2015), NTRS 20150004602, equations 4-8, Tables 5, 7 and 10.
https://ntrs.nasa.gov/citations/20150004602
Q = mdot*cp*(1-exp(-UA/(mdot*cp)))*(Tskin_effective-Tin).
Original constant-UA benchmark calibration days: 2/4/3/5; held-out: 6/7/8. The benchmark uses measured skin
and water conditions and aggregate means. It checks garment heat transfer, not
the complete low-pressure Mars physiology. No fixed metabolic subtraction or
body-temperature controller is used. Mean-state calculations lose covariance.

Condenser: Althausen et al., AIAA 2006-1337, p.4 dimensions.
https://doi.org/10.2514/6.2006-1337
Straight laminar channels and root-cooled wet fins are assumed. Conductivity is
an assumed POCO HTC graphite proxy, not measured PG-45 data. The three-zone
series ventilation, equal free volumes, ideal control and prescribed wall/radiant
conditions require validation. Sizing does not feed humidity changes back to JOS-3.

Reheater: Quinn, Strange and Jennings (2013), NTRS 20130011141, Tables 2-3.
https://ntrs.nasa.gov/citations/20130011141
Counterflow conductance and constant NASA package conductance density scale
mass/volume. Reversing the reference cooling duty to heating is an extrapolation.
Detailed hydraulics, fit, suit-wall behavior and full physiological validation
remain outside the demonstrated model accuracy.

PLOT ORDER AND REPORTING
Stage 1 creates figures 1-9: metabolic sources, nominal EVA, LCG comparison,
astronaut moisture, suit-air temperature, off-nominal comparison, nominal body
heat balance, off-nominal body heat balance, and dynamic-UA validation/fit.
Stage 2 creates figures 10-14: suit-air
condensate, suit airflow, condenser trade, supply compliance, and reheater.
The command window shows five physiology tables and four hardware tables.
Additional body-balance/temperature and literature diagnostics remain in the MAT
file. Infeasible hardware instead prints its feasibility/failure table.

The reheater retains internal control samples plus interval endpoints: for
960 half-minute intervals at a 1-second internal step, 960*(30+1)=29,760 samples.
These arrays are intentionally longer than the interval-average histories.

PLSS AIR AND WATER TABLE
PLSSAirAndWater reports off-nominal mean/minimum/maximum values. Air is sampled
between the condenser and reheater. Means are duration weighted; instantaneous
control samples/endpoints supply air extrema and reheater-return extrema. Water
rows include LCG inlet/outlet, reheater inlet/return, fin-root liquid boundary,
and fixed water-property reference temperatures. The fin-root boundary is not
a bulk coolant temperature prediction; no coolant inlet/outlet circuit is solved.
The condenser property reference is the configured root-floor input; the stored
water density reference is the selected design root floor.

INDEPENDENT REHEATER WATER BOUNDARY
The reheater supply is configured separately in PLSS_Thermal_Sizing.m at
18.3 C. Its fixed-UA flow controller splits available water between the warmer
and bypass, then recombines the two streams. Mixing energy is conserved.
This mixed return is not imposed on the LCG. The LCG receives the independently
controlled inlet history calculated in stage 1. The full shared radiator,
refrigeration power, PCM inventory and hydraulic network are not solved.

METABOLIC / PHYSIOLOGY OUTPUT FACTOR OF SAFETY
MetabolicFOS in Metabolic_EVA_Sim.m is a configurable, finite output-load
multiplier >=1. Current setting 1.2 adds 20%; 1.0 leaves loads unchanged.
The metabolic rates, both JOS-3 runs, heat balances, console tables and plots
are calculated at physical demand, independently of FOS. Only after these
calculations finish are separate Data.Simulation.Sizing.Nominal and OffNominal
structures created. Each has factored Metabolic and PhysiologyLoads tables,
plus a SizingProfile for hardware. The original case tables remain unchanged.

Metabolic power and physiological heat/power, moisture-rate and accumulated
water-load outputs are multiplied once. Temperatures, RH, time, pressure,
ventilation/water flow, calibration observations and numerical closure errors
are not multiplied. These are design allowances, not a new physiological run.
The sizing profile retains original physical humidity/source reconstruction
fields. DesignMoisture_g_min and the remaining-target-deficit column
receive FOS; temperatures, flow and stored-heat states do not. sizeEVARH reconstructs
factored regional moisture sources once using Design/PhysicalMoisture. This
preserves its conservation checks and avoids applying FOS twice. Condenser
and reheater duties are recalculated for the factored moisture at the original
state/flow boundary conditions; their resulting volumes are not multiplied
again. Metabolic and other factored physiological loads are transferred in
Hardware.DesignLoads for component requirements; thermal setpoints do not
change merely because a load factor is applied.

The hardware script uses the factored off-nominal sizing profile. Sensitivity
changes apply relative to that factored baseline. Component performance shows
the applied FOS. Interface validation checks both original profiles and their
factored copies against the configured FOS. Rerun Metabolic_EVA_Sim.m then
PLSS_Thermal_Sizing.m after changing FOS or updating this handoff.

FIGURE 7 HEAT-STORAGE SCREENING
Nominal physiological results are shown without FOS in two panels: grouped
heat production/removal and cumulative storage (kJ/kg). The storage-rate panel
has been removed. Cumulative storage integrates signed interval-average storage
using interval durations and starts at zero at EVA start, after preconditioning.
The plot marks the maximum and the configurable 3.0 kJ/kg nominal reference
from NASA V2 11011 (OCHMO-TB-050 Spacesuits, p.6). This JOS-3 comparison is a
screening check, not a formal NASA-model compliance determination. The LCG controller uses a lower adjustable target. Hardware heat-storage
screening is reported separately from condenser/reheater feasibility.

CONDITION-DEPENDENT GARMENT CONDUCTANCE
Default LCG.Model is "LiteratureDynamicUA". Set it to "LiteratureUA" in the
main script to recover the original constant-UA model. Both use the published
Eq.8 effectiveness relation and the same implicit body energy-balance solver.
No FOS enters the physical conductance or physiology calculation.

Source: Bue et al. (2015), Experimentally determined overall heat transfer
coefficients for spacesuit liquid cooled garments, Table 10, printed p.17.
https://ntrs.nasa.gov/api/citations/20150004602/downloads/20150004602.pdf
NASA documents workload/flow dependence and history effects in sections III.C
and III.A. Table 10 provides paired EMU UA, metabolic and water-flow observations.
Its 16 records are stored as DynamicRawTable10 by buildEVAData. The missing
dataset is added automatically on the next simulation run without clearing
existing results. No new archive or run tracking is created.

The active dynamic-UA model has been restored to the original bounded linear
fit, selected explicitly by LCGFitSettings.SelectedFamily="Linear":
UA [W/K] = 9.45181615 + 0.0292319995*M [W] + 228.671076*mdot [kg/s].
It is fitted to days 9/10/11; day 12 stays held out. Linear feature scales in
LCGFitSettings change coefficient units but not this physical regression.
Held-out RMSE is approximately 2.031 W/K. Calibration-only grouped cross-validation
of Linear/LogAdditive/PowerLaw is retained as a diagnostic; it no longer selects
a different model automatically. Selected coefficients feed every solver trial.

Workload/flow remain clamped to calibration ranges (237.09-503.50 W;
0.004914-0.025200 kg/s); output UA is bounded to 15.00-31.56 W/K.
Outside-range samples remain flagged. These fits are our empirical regressions,
not NASA-published transient garment correlations. Source data describe gross
metabolic expenditure M; current Qgen-based simulation uses the same numerical
function as requested, an additional input-basis approximation.

Figure 9 retains the held-out dynamic-UA comparison and adds a TWO-DIMENSIONAL
UA-versus-workload plot at three fixed water flows: calibration minimum, baseline
and configured maximum. Measurement markers have varying flow, so they are not
all expected to lie on one fixed-flow curve. The clamped portion above the
workload calibration limit is visible. The constant-UA graph remains removed;
its calibration still supplies baseline water flow and the optional fixed-UA
fallback. Figure 3 remains cooling duty, inlet temperature and flow rate.

The model is quasi-steady: conductance changes with operating conditions,
without an invented wetness multiplier or lag time. Sweat/contact hysteresis,
water-inlet-temperature effects, garment fit and long-duration Mars conditions
remain unvalidated. In particular, the 1351 W EVA peaks are well outside the
training envelope. This model cannot establish that the heat-storage problem
is resolved. Rerun both scripts and inspect cumulative storage and core
temperature after the new physical histories have been calculated.

CONTROLLER AND MODEL LIMITS
Stored heat starts at zero after preconditioning. The controller uses a fixed
inlet temperature range and increases flow before lowering temperature.
Accepted flow is retained near the stored-heat target and released gradually
below its deadband, as described under LCG FLOW CONTROL below.
Body, water and suit-air conservation checks remain active. Temperature/flow
searches assume monotonic cooling response. Pump hydraulics, cooling-source
capacity and actuator response are not modeled. Heat-storage failures remain
visible; no stored heat is clipped. Rerun both scripts after model edits.

EXTERNAL WORK CORRECTION AND QGEN INPUT
The physiological demand is now Qgen = M - Wext. Main-script ExternalWork inputs
use ICES-2021-365 Tables 7-8 device power: nominal 0 W, aerobic 201 W, resistance
45 W. Above-nominal uses the existing 80%-of-resistance mapping for BOTH source
metabolic activity and external work, giving Wext=36 W. Off-nominal walking uses
the resistance reference and its 45 W external-work assumption.

Mars and suit adjustments are applied to M first; the published Wext is then
subtracted without applying Mars/suit factors to it. This is an explicit proxy
assumption, not a measurement of external work during EVA walking or tool use.
At the current input settings, Qgen is nominal 167.028 W, above-nominal 308.739 W,
resistance 388.472 W, aerobic-proxy 1150.160 W and off-nominal walking 337.565 W.
The source metabolic rates keep their original precision (5197/3.6, for example),
so results need not exactly match a paper table rounded to integer watts.

Both time histories save MetabolicRate_W (M), ExternalWork_W and HeatGeneration_W
(Qgen). Only HeatGeneration_W feeds runJOS3Profile, including preconditioning,
control, body heat balance and the resulting moisture/cooling loads used for
hardware sizing. All physiology activity-ratio calculations now receive Qgen,
as requested. This also changes the input to the workload-dependent UA and
respiratory correlations: those empirical relationships were originally based
on metabolic expenditure, so their use with Qgen is an additional approximation,
not a new validation. Original literature UA measurements and calibration checks
remain unchanged; they must not be represented as heat-corrected measurements.
Qgen is assumed to include all heat production, including thermogenesis. No
additional shivering or nonshivering heat is calculated or added. The legacy
Physiology.MetabolicHeat_W field equals prescribed Qgen, not gross expenditure M.

The Metabolic Rates command-window table reports only Qgen minimum, average
and maximum for nominal and off-nominal cases. M and Wext remain in saved data. Operational activity plots show Qgen; Figure 1 remains a
clearly labeled original source-M comparison. Source datasets are not altered.
The separate sizing copy factors M, Wext and Qgen once, preserving Qgen=M-Wext;
physical runs, temperatures and controls remain unfactored. Interface validation
checks the energy subtraction before hardware sizing. Rerun both scripts to
replace existing results generated without the external-work correction.

COMPLETE QGEN HEAT SOURCE
QgenIncludesThermogenesis=true records the prescribed-heat assumption in the
main inputs and prevents reuse of cached histories from the former additive
thermogenesis configuration. Shivering/nonshivering heat-source equations and
their unused age/BAT parameter calculations are removed. Other physiological
responses (sweating and skin blood flow) remain active. Rounded activity heat
distribution fractions are normalized so total tissue production equals Qgen
exactly, checked in every body timestep. This same source is used during
preconditioning, control trials and accepted EVA timesteps. The model therefore
does not generate extra heat if the skin/core becomes cold; that is the stated
scenario assumption, not an independently validated response to overcooling.

BOTH HEAT-BALANCE FIGURES AND NEGATIVE STORAGE
Figures 7 and 8 use the shared plotBodyHeatBalance reporting function for nominal
and off-nominal EVA respectively. Both show prescribed Qgen, actual cooling and
signed accumulated thermal storage from EVA start, with identical reference lines.
The 3 kJ/kg line remains a nominal screening REFERENCE on the off-nominal plot.
Negative storage means the body has lost heat relative to its starting thermal
state. It is not negative absolute heat content, nor an energy-closure residual.

The inlet temperature bounds are fixed at the configured values (currently
10 to 18.3 C). Flow stays between the chosen baseline and maximum. The fixed
radiant boundary can still remove heat at zero LCG flow; negative storage
remains physical signed storage relative to EVA start and is reported.

AIR AND VAPOUR HISTORY
Both the current and original pre-restructure runJOS3Profile use steady gas
energy/moisture balances inside each body timestep. Previous zone air temperature
and humidity initialize the iterative solve, but do not define finite gas-energy
or vapour storage equations. Those values are therefore a numerical starting
guess, not a physical residence-time delay. Instantaneous local phase equilibrium
also applies. Body tissue temperatures, retained sweat and zone condensate masses
DO persist and influence future results. Respiratory vapour responds directly to
prescribed Qgen; sweat/retained evaporation also depend on evolving body/liquid
states. Changed workload and cooling can shift the relative contributions, so
rapid gas responses do not prove that body or retained-water history was reset.
A physically transient air response requires defined gas masses/volumes, heat
capacity and vapour-inventory time derivatives; plot smoothing is not equivalent.

THERMAL SIZING INPUT TRANSFER
Run Metabolic_EVA_Sim.m to completion, then PLSS_Thermal_Sizing.m.
Sizing reloads the current saved simulation, including environment, controlled
water histories and post-simulation FOS loads. Editing EVA inputs alone does
not update results; the simulation must finish and save first.
Empty sizing inputs inherit saved EVA supply RH, LCG reference inlet water
temperature, and off-nominal peak LCG water flow. The peak-flow default is
a sizing assumption for the independent constant-flow reheater circuit, not
a shared instantaneous circuit. Numeric reheater inputs override these defaults.
If all simulated LCG flows are zero, specify a positive independent reheater
water flow explicitly. Component calculations remain off-nominal only.

LCG FLOW CONTROL
Flow increases first; inlet temperature is lowered only at maximum flow.
The controller remembers only the previous accepted flow. Within 0.05 kJ/kg
below the storage target it holds that flow, then releases it gradually at
10 kg/h per minute below the band. Both settings are editable at the top of
Metabolic_EVA_Sim.m. Flow increases are immediate; no upward lag is imposed.
All trials use the same starting body state. The accepted flow is used in
the actual coupled heat/moisture calculation, not just smoothed in the plot.
The baseline remains the minimum (including zero); maximum remains configured.
Smoothing can retain cooling longer after a workload decrease; inspect signed
stored heat and core temperature after rerunning. No heat is clipped.
Re-run the EVA simulation before sizing: old MAT histories use obsolete fields.

THERMAL INTERFACE
Each case exports physical BodyPathways, Ventilation and BoundaryConditions
under ThermalInterface. Radiation is heat transferred to the inner suit, not
external heat rejection. Prescribed inner radiant temperatures are exported.
Body pathways close Qgen = LCG + wall radiation + ventilation sensible and
latent heat + body storage. For ventilation use either body sources or gas
boundary states, never both. Net return vapor accounts for local condensate
inventory; it is not additive to the body's vapor source.
Sizing applies FOS once to receiving-path powers in ThermalPathwayLoads;
physical temperatures, flows, gas states and body storage stay unfactored.
The condenser continues using its existing gas-state/moisture-load interface,
not the alternative pathway powers. Return revised wall temperatures through
another EVA run if an external thermal network predicts different boundaries.

THERMAL SYSTEM SIZING SUMMARY TABLE
Reports.ThermalSystemSizing is printed and saved by both scripts. Columns are
Quantity, Unit, Basis, and nominal/off-nominal minimum, average and maximum.
The EVA table includes all dimensional physical histories (body heat pathways,
core/skin temperatures, regional air temperatures/RH, vapor and condensate,
LCG water states/flow/UA, stored heat, deficits and conservation diagnostics),
plus supply/return humidity ratios, gas pressure/flow, LCG temperature rise,
water heat-capacity rate, prescribed radiant boundary and cumulative energies.
Average values are timestep-duration weighted. Cumulative-energy averages
integrate the piecewise-linear accumulated energy; their extrema include EVA
start. Regular body-state statistics use the saved interval endpoint states.
At zero LCG flow, outlet temperature is a reporting convention, not a prediction
of stagnant-water temperature. Radiation is heat transferred to the suit
interior; ventilation sensible/latent rows are alternative source descriptions
and must not be added again to loads computed from the gas states.
The Basis column separates physical histories from FOS design allowances.
Thermal sizing appends actual condenser/reheater duties, removal rates, air
states, fin-root temperature, water branch/bypass/mixed-return states, required
UA, regional phase-change terms and fixed package mass/volume/storage capacity.
Hardware averages use internal sample durations; zero-duration final endpoints
participate only in extrema. Interval phase terms use interval durations.
These hardware results already use the configured FOS moisture loading; they
are not globally multiplied by FOS again. Nominal hardware columns are NaN
because only off-nominal hardware is sized. No hardware rows are appended when
no feasible design exists. Fixed design quantities have equal min/avg/max.
Refrigeration electrical power, external rejection, pressure drops and coolant
conditions not solved by these scripts are not invented in this table.
Rerun EVA simulation, then thermal sizing, to populate the new saved reports.

ThermalSystemSizing excludes humidity, moisture-generation/removal rates,
retained-liquid/condensate inventories and collected-water capacity statistics.
These remain in the dedicated reports and saved detailed histories. Thermal
latent/phase-change duties, coolant water flows and water temperatures remain.

DYNAMIC INNER LINER
The EVA script enables a single liner node with editable initial temperature,
reference temperature, heat capacity and conductance. Defaults of 5000 J/K,
5 W/K and 16 C reference are preliminary assumptions. Preconditioning and each
accepted EVA step advance the liner using signed body radiation. The starting
liner temperature is the radiant boundary for all trials in that step.
ThermalInterface.Liner contains temperatures, storage and onward heat flow.
Use Radiation_W when the receiving network includes the liner. Use
LinerOnwardHeat_W when the receiving network starts downstream of it.
The thermal sizing summary includes these physical histories. Set Liner.Enabled
to false to use the prescribed radiant temperature again.
